## Phases, in this order
### Phase 3 - Core public pages (bilingual, DB-driven, SEO metadata + hreflang + sitemap entries)
- About: testimony/faith journey, vision, mission, values, statement of faith, goals/outreach, photo/story section. Content from SiteSettings fields (add fields via migration if missing, editable in admin Settings), with demo fallbacks clearly marked.
- Devotionals & Bible resources: daily/featured verse, a list of devotionals/articles/Bible studies with search + category filter + type filter + pagination (server-side, URL search params), a detail page /[locale]/devotionals/[slug] with scripture references shown clearly, sanitized rendered Markdown, and social share buttons (copy link, Facebook, X, WhatsApp, email using plain share URLs, no third-party SDKs/trackers). Per-post Open Graph metadata.
- Missions & Outreach: upcoming and completed lists, detail page /[locale]/missions/[slug] with location, dates, description, the post-trip report, the volunteer/participation info, and a linked gallery.
- Media Center: sermons, worship, podcasts/audio (native <audio controls>), YouTube embeds via youtube-nocookie.com with a click-to-load facade (no YouTube requests until clicked), photo galleries with an accessible lightbox. This resolves the earlier review NIT that pasted media links are not rendered publicly.
- Privacy Policy and Terms pages with sensible template text, clearly marked 'template - have it reviewed', describing the prayer/contact/donation data handling actually implemented.
### Phase 6 - Prayer request + Contact forms
- Prayer form: optional name/email, a 'submit anonymously' toggle that disables and clears those fields, a request body, an explicit unchecked-by-default consent checkbox for possible public sharing, a privacy notice, Turnstile, honeypot, rate limit (per hashed IP; never store raw IPs), and a success state. Stores to PrayerRequest.
- Contact form: name, email, kind (General / Testimony / Volunteer), subject, message, testimony-share consent, the same spam protections. Stores to ContactMessage.
- Admin inbox (already exists read-only): add status changes and notes if needed, a 'publish as public prayer/testimony' flow ONLY when consent is true (admin-edited public text, no personal info shown), delete, and a configurable retention purge (for example an OWNER setting in months plus an admin 'purge old' action). Optional public 'prayer wall' listing ONLY published, consented items.
- Admin email notification via Resend (link only, no request body in the email).
### Phase 7 - Media uploads (Vercel Blob)
- Admin upload UI for images and audio (drag-and-drop + file picker, progress, MIME/size allow-list validated server-side: images jpeg/png/webp up to ~8 MB, audio mp3/m4a up to ~100 MB; use Vercel Blob client uploads with a server token route for large files), alt text required for images, media library grid with search/filter, galleries (create, order items, link to an event), and pick-from-library for post/event cover images and the site logo. Replace the URL-only fields with picker + URL fallback. Fix the review NIT about a generic upload hint on image-only fields. Delete removes the blob too. Short video files are not required; video stays YouTube embeds.
- Use next/image where appropriate (configure remotePatterns for the Vercel Blob host).
### Phase 8 - Donations (Stripe, USD)
- Support page: explains the mission and how gifts may be used (demo text), preset amounts + custom amount (server-validated min/max, USD), one-time or monthly, a clear disclosure (processor = Stripe, no card data stored, not tax-deductible unless verified, refund/contact info), redirect to Stripe Checkout (mode payment or subscription), and success/cancel pages. Stripe sends the receipts. Optional Stripe Customer Portal link for managing monthly gifts.
- Webhook route /api/stripe/webhook: raw body + signature verification, idempotent processing (store the event id), records to a Donation model (amount, currency, interval, status, Stripe ids, optional donor email; NO card data). Handles checkout.session.completed, invoice.paid, charge.refunded, customer.subscription.deleted.
- Admin donations page (OWNER, and EDITOR read-only if the existing design allows; decide and document): list, filters, totals for the selected period, CSV export, and Stripe configuration status. donationsEnabled in Settings toggles the public giving UI.
